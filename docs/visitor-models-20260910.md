外观选择新增「暗黑少年」（noir）和「角饰女孩」（rose），原有熊女孩、猫女孩、九尾狐继续使用。点击空椅或使用「定位角色 → 在这里放置角色」选择外观；点击床位可躺下休息，之后通过「定位角色 → 醒来，坐一会儿」回到坐姿。

面向 +Z、Y 向上、坐垫接触面为 y=0，沿用现有访客的坐标约定。暗黑少年站立高度 1.3，角饰女孩按最窄座位间距等比例缩至约 1.135；转头时最宽分别约 0.583 和 0.582。所有 32 个位置及两张床的边界检查通过。

贴图使用原始 1K PBR。发色、眼睛、上衣、下装接入原有可选换色着色器；默认颜色保留源纹理。坐姿与站姿 GLB 的嵌入图片逐字节相同，运行时共享 GPU 纹理。四个 GLB 由当前网站的带哈希资源地址提供，沿用用户素材的 R2 待批准标记，未另行上传 R2。

## 行为与加载

- 坐着：缓慢呼吸、间隔眨眼、轻微转头；每个访客的节奏由身份种子决定。
- 躺下：闭眼、微弱呼吸，原有床位占用与休息状态同步继续工作。
- 醒来：保持人物和外观，回到同一床位的坐姿。
- 问候与爱心：沿用在线访客的点头及气泡互动、冷却与休息保护。
- 配色、名字和姿势：沿用原本的服务器访客记录与本地外观偏好。

没有增加独立 AI、骨骼或渲染循环。新眼睑按两个人物的脸部单独标定，使用原有面部动画着色器。减少动态效果时停止呼吸、转头和眨眼，休息时仍闭眼。预览只请求当前选择的角色，切换后释放旧预览资源；场景继续按当前房间所需角色加载并实例化。模型失败时展示现有重试提示，其他角色和小屋可正常使用。

## 文件与复现

主要接入点：`app/visitor-appearance.json`、`visitor-appearance.ts`、`visitor-figure-profiles.json`、`visitor-motion.ts`、`visitor-eyelids.ts`、`visitor-rest-poses.json`、`visitor-preview.tsx`、`globals.css`，以及资源目录和生成的资源清单。服务端从同一人物目录校验 ID，无需另建访客接口。

在独立 Blender 工程运行 `scripts/prepare-guest-figures.py`，参数为人物 ID 和对应原始 GLB；两个人物生成后执行 `python3 scripts/register-guest-profiles.py`，同步标定参数；最后运行 `npm run assets:prepare`。程序的 `--prepared` 仅用于本机从归一化预览导出继续迭代。原始 800×1000 正面图上的眼部描点保留在登记脚本内。

## 验证

类型检查、生产构建、资源 8 项检查、外观接口、32 个座位／休息／起身／互动接口检查通过；既有 986 条生活导航路线和占位模拟通过。坐姿模型、完整躺姿和运动边界测试扩展到五个人物，验证原纹理一致、UV／法线完整、床垫上方接触、相邻座位间距、呼吸时脚部固定和减少动态效果。

本地浏览器完成新人物选择、入座、换装保存、第二页面读取、床位休息与醒来；网络阻断角饰女孩时可继续选择暗黑少年，解除阻断后恢复，房间切换正常。正面、侧面、闭眼、躺姿及正式小屋截图在本机 `output/playwright/visitor-*`。验证使用隔离本地数据，不修改线上访客或公开内容。

同屏两个新访客的本机 Chrome 约 4 秒短采样：桌面 1440×1000 为 44 FPS／P95 33.3 ms；手机尺寸 390×844 触屏模拟为 55 FPS／P95 33.3 ms；减少动态效果为 60 FPS／P95 17.4 ms。四个角色资源均返回成功，无页面错误或横向溢出。结果受机器负载影响；手机尺寸模拟不是实体手机或满员压力测试。
