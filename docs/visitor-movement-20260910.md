# 访客换位、咖啡与房门（2026-09-10）

## 使用方式

- 首次放置角色保留原来的入座界面。之后点击空座位，角色先起身，经安全通道走过去，再坐下；点击床则在到达后躺下。换位时镜头保持当前位置。
- 点击自己的角色或「定位角色」，可选择「看看手机」「喝口咖啡」。角色也会错开时间进行短暂坐姿活动；休息中不触发这些动作。
- 管理者在展品详情中点击「编辑作品」并修改作品名称。展台卡片、悬浮提示、探索列表和详情使用同一份服务器标题，其他访客也能看到。
- 六处房间连接口增加橡木框、长虹玻璃、内藏式移门与金属把手。角色靠近时开门，离开后缓慢关门；沿用原有门洞和墙体剖切，不移动房间家具。

## 实现

- `scripts/generate-visitor-routes.ts` 从现有家具坐标、32 个座位和生活系统导航图生成 496 条双向路线，保存在 `config/visitor-routes.json`。所有落脚点和步行段经过家具与墙体碰撞检查；入座和离座段只允许穿入对应座椅的接触区。
- `app/visitor-travel.mjs` 由服务器生成带时间戳的行程：起身、离座、步行、进入座位、坐下／躺下。客户端不能提供任意坐标或缩短持续时间。目标与出发座位在行程完成前均保留；狭窄通道一次只允许一名访客换位，其他人得到简短等待提示。
- 沿用现有五个人物的坐姿、站姿、纹理与实例化渲染。`visitor-pose-morph.ts` 利用相同源模型的 UV 对应关系建立连续姿势；绯狐用完整站姿拓扑向坐姿收拢，避免展开已压缩尾巴时出现裂缝。无新增 GLB 下载，无逐帧 CPU 顶点重算。
- `visitor-motion.ts` 增加落脚、迈步、起身、持物的顶点动画；`visitor-hand-poses.ts` 保存各人物的握持基准，原有脸部动画、换色、站姿与休息资源继续复用。
- `visitor-props.ts` 提供低面数手机、咖啡杯及错开的动作时间。自动活动每个角色按身份错开，在 48 秒周期中短暂出现 7 秒；主动互动约 10 秒，服务端有 2.5 秒重复操作限制。
- 生活系统读取行走角色当前位置和前方位置，提前让路。门扇收进墙体，不占用通行宽度；减少动态偏好下门直接切换开合、关闭非必要持物与步态摆动，保留必要的位置过渡。
- 成品咖啡移至与咖啡机、纸巾都分离的取餐点；液面低于内壁，杯碟高度跟随杯型缩放。所有咖啡杯的把手改为外侧 C 形结构，消除完整圆环穿进咖啡液面的白色凸块。

## 验证

- 32 个座位的 496 条路线连通；步行段通过原有 `floorClear` 和 `segmentClear`，按 16 毫秒采样确认过渡没有位置跳变。
- 五个人物姿势转接检查通过，没有异常拉长的三角面；原有眨眼、休息姿势与纹理一致性测试通过。
- 服务端入座竞争、双座位预留、快速换位限制、休息／醒来、手机／咖啡动作、身份与 HTTP 边界检查通过。运行镜像依赖检查覆盖新行程模块与配置。
- 浏览器实际点击验证沙发至工作椅约 10.35 秒、书房至床约 35.53 秒，均能完整到达；随后可从床上醒来。换位不打开编辑窗口。
- 浏览器修改展品标题为测试名称，确认公开接口、详情与场景提示同步，固定的「AI · 半导体项目」文字不再出现。测试只使用隔离的本地数据。
- 桌面 1440×1000、手机尺寸模拟 390×844／DPR 2、减少动态三组各采样约 4 秒，均约 60 FPS，95% 帧间隔约 16.7–16.8 毫秒；无页面异常或横向溢出。手机结果来自桌面 Chrome 模拟，不是实体手机跑分。
- 原有生活导航、咖啡区家具间距、全屋布局、管理权限和服务器保存测试通过。黄昏太阳与天气算法没有修改。
