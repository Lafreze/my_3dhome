# SATORI · 小屋与咖啡厅

一个可本地运行、按 2×2 布置的三维个人展示屋：左上书房、右上客厅、左下卧室、右下展示区，南侧是一间横跨双房宽度的咖啡厅。原创空间采用橄榄绿、灰泥、木材、亚麻与陶器；家具、绘画和声音由本地代码构建；木材、皮革、织物和灰泥结合了已下载的 CC0 PBR 素材与程序纹理。新增的王冠兔使用用户提供的 GLB，经本机 Blender 优化后随本地项目加载；不依赖模型 CDN、图片、字体或音频服务。用户选择定位或城市后连接天气服务；使用已保存的电视或电脑网址时连接相应外部服务。素材来源见 `THIRD_PARTY_ASSETS.md`。

## 本地运行

```sh
npm install
npm run build
npm start
```

打开 http://127.0.0.1:3000/ 。服务只监听 `127.0.0.1`。如果端口被其他应用占用，可使用 `KOMORI_PORT=3001 npm start`。

开发模式使用 `npm run dev`，同样只监听本机。

## 房间与俯瞰

底部房间下拉菜单切换书房、客厅、卧室、展示区、咖啡厅、整屋全景与「房屋俯瞰图」；俯瞰图从正上方查看 2×2 主屋与南侧横向咖啡厅，隐藏门洞上方墙体并显示房间标记，点击其中的房间即可进入。外墙随观察方向做剖切，保留窗景与完整模型，避免墙壁挡住家具。

- 书房：保留原先的工作台、书架、阅读区和全部互动。
- 客厅：沙发朝向大电视；电视柜分区放置 Switch、游戏主机、音箱和游戏收藏，桌上有无线手柄、遥控器和书杯。
- 卧室：床头软包、枕头、床尾织物、双侧床头柜与灯、衣柜内部挂衣和叠放收纳、床尾长凳与洗衣篮。
- 展示区：独立的原创三联画、轨道照明、用户提供的可转动王冠兔、可抬起玻璃展罩的收藏柜和观看长凳。
- 咖啡厅：16 × 8 单位（约 10 × 5 米），从卧室与展示区南侧门洞进入。西侧吧台保留独立操作通道，中央共享桌、东侧皮革卡座、南侧玻璃门窗与露台；全部椅子面向对应桌子。咖啡机操作面朝向吧台后方，前方为点单和取餐区域。

咖啡厅可萃取咖啡、启动手冲、开合点心柜、切换每日特调、调整卡座皮革颜色与独立吊灯。全屋照明总开关联动全部房间；近看设备时隐藏上方灯具，俯瞰时剖切顶棚。`node scripts/check-cafe.mjs` 检查家具占地、朝向、通道和扩建连接；`node scripts/check-wall-cutaway.mjs` 检查背墙隐藏、共享墙双侧、俯瞰与临界角防闪烁。

房间中心间距为 8 × 6.8 单位，每单位 0.625 m。四条房间连接门洞宽 1.4 单位，沿各房间主要通道布置。`node scripts/check-house.mjs` 检查四个房间的位置、家具边界、碰撞、主要路线、衣柜开启范围、沙发电视对齐及视频链接解析。

## 电视播放

客厅直接点击茶几上的遥控器可打开电视控制；也可点击电视，或从「探索」选择「家庭影院」，再点「打开电视」。

- 粘贴 YouTube 视频、短链接、Shorts 或直播链接，按保存播放；支持链接中的起播时间。网址和电源状态保存在当前浏览器，刷新后进入客厅自动静音播放，可在播放器内开启声音。
- 可输入 MP4、WebM、Ogg 视频文件直链，也可选择本地文件。普通网页链接不会冒充视频流。
- 本地视频只通过浏览器临时地址读取，不上传、不能跨刷新恢复；可加载 VTT 字幕。本地视频、视频直链与 YouTube 均直接显示在客厅电视屏幕，随镜头变化产生正确透视，并被家具遮挡。YouTube 保留官方原生播放器和控件。
- 收起遥控器后继续播放；离开客厅停止播放器，重新进入时使用保存的来源启动。关闭电视电源后再次进入或刷新也保持关机，直到手动打开。有网络或嵌入权限限制时显示反馈，可用「原网页」打开影片。

YouTube 在线播放受网络、浏览器播放规则与影片嵌入权限影响。接口按照 [YouTube 官方嵌入文档](https://developers.google.com/youtube/iframe_api_reference) 配置，携带当前页面来源，不代理视频。

## 电脑与独立画框

书房直接点击电脑模型，输入完整 HTTP / HTTPS 网址后保存。进入书房自动在三维显示器内显示网页；关闭电脑后刷新仍保持关闭。部分网站的 CSP / X-Frame-Options 不允许嵌入，设置中可用「独立打开」访问，项目不绕过这些限制。

客厅两幅画和展厅三幅画各自可点击编辑，也可从「探索」选择对应画框。在画作面板切换画框时，相机跟随进入对应房间；每幅画都可恢复自己的原作。支持 JPG / PNG / WebP，原图上限 30 MB，浏览器将最长边缩小至 1600 px，并使用 WebP 压缩；完整适配画框比例，留边而不裁切。图片分别存入当前浏览器 IndexedDB，刷新后恢复，不上传服务器。

电视、电脑和画作设置不跨设备、浏览器或域名同步；清除浏览器数据会移除它们。个人资料的 JSON 导出仅包含资料和作品，不包含这三类独立设置。

## 展示与互动

拖动环顾、滚轮或双指缩放。点击物件后镜头靠近；不再显示地面金属选择环，简洁的物件卡提供对应操作；卡片与控制栏跟随实际可视区域，缩放时保持在屏幕内，矮窗口中卡片内部可滚动；「探索」也能通过键盘访问当前房间的物品，整屋模式下可访问各房间的全部互动对象。

- 书房作品墙和工作台：打开作品集，浏览封面、分类、说明及可选作品链接。
- 桌上肖像：个人介绍。相机：最多 6 张本地照片，无照片时展示原创视觉习作。
- 抽屉：有内部结构的滑动开合；雕塑：平滑旋转；工作椅：朝向电脑，前后拉出 / 归位。
- 唱片机：旋转唱片、唱臂起落，以及浏览器合成的原创旋律。
- 咖啡：续杯热气；三处植物：各自响应浇水，窗边植物带细微摆动。
- 沙发、皮革椅、地毯：更换配色。
- 底部「灯」是全屋照明总开关，同时控制主屋和咖啡厅的顶灯、台灯、床头灯和展厅射灯。单盏灯仍可独立开关，总开关重新开启时保留各灯的状态。电视与电脑屏幕、窗外自然光不受总开关影响。
- 蘑菇灯与折臂工作灯：分别开关。工作灯含双支臂、轴铰、螺钉、配重底座与闭合的灯罩内外壁，灯源随灯头共同变换。窗景：默认跟随现实时间，点击右上角「时间与天气」授权定位或搜索城市；也可切换「自由预览」，手动选择四个时段与晴、阴、雨、雪、雾、雷雨。
- 书架：打开手记，编辑并本地保存随记。

支持全景复位、缩放、桌面全屏、弹窗焦点约束、Esc 关闭及减少动态效果偏好。手机构图会自动适配宽高比；真实设备触摸体验仍以设备浏览器为准。

## 现实时间、天气与窗外空间

- 首次打开按设备时间显示光景，天气显示「待定位」。点击「使用当前位置」才请求浏览器定位；若该网站已获定位权限，下次打开自动获取位置。拒绝、超时、网络失败均可改用城市搜索或手动预览。
- 位置只存在当前页面内存中，查询前经纬度取两位小数（约 1 km），不写入本项目服务器或浏览器存储；取整坐标随请求发送到天气服务。天气直接由 [Open-Meteo](https://open-meteo.com/en/docs) 提供，无需密钥，默认每 15 分钟刷新；时钟每 30 秒更新。重新打开需再次选城市，或使用浏览器已授权的定位。
- 显示当地时区、温度、天气、风速和数据时间。Open-Meteo 的 current 数据是天气模型当前估计，不是屋外传感器；失败保留上次记录并标记，超过 90 分钟的数据会标为未更新。城市名称来自 [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api)。
- 太阳方位与高度按经纬度、UTC 日期和 [NOAA 太阳位置公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF) 计算，处理南北半球、极昼与极夜。场景固定北为 −Z、东为 +X；入射方向与窗景中的太阳一致，太阳落山后不再提供直射日光。未定位时的光景仅按设备小时估计，不冒充当地日出日落。
- 四扇窗观看同一个三维室外场地：书房北窗看水岸花园、花箱、池边廊架与远处屋顶；卧室西窗看围合庭院、树木、长凳与水钵；客厅东窗看带咖啡店、斑马线与低层建筑的街巷，展示区东窗看带桌椅与陶盆的前庭花架。两扇东窗实际相隔 6.8 场景单位，具有相同的地理方向和不同视差。定位改变时间、气候与太阳位置；这片原创庭院并非定位点的真实街景。
- 窗景通过每扇窗的真实位置、朝向和观察点进行离轴投影，镜头移动时有前后景视差。四间屋共享阳光和天气，雨丝斜向按风向投影到各扇窗，雨量控制密度；雪使用独立雪花，雾影响远景能见度，夜晚街灯与邻居窗内亮起暖光。手动雷雨无频闪。
- 窗户补充密封条、分格玻璃、窗扇把手、螺丝、铰链、窗台轨槽；室外包括独立叶片、铺路石、篱笆、坡屋顶、檐沟与落水管。静态结构按材质合并，叶片使用实例化，窗景缓存复用；后台页面暂停三维绘制。

## 换成自己的内容

右上角调节图标打开编辑器：

1. 修改名称、短标题与个人介绍。
2. 编辑、添加或移除作品，保留 1–12 件；前三件的封面同步到屋内画框和电脑屏幕。初始三件是原创示例，不代表用户真实履历。
3. 上传 JPG、PNG 或 WebP 封面和照片。单张原文件上限 20 MB，上传后在本机缩小到最长边 1000 像素。
4. 点击「保存布置」。资料、作品与照片保存在当前浏览器的 IndexedDB；旧版 localStorage 内容继续兼容读取，在下次保存成功后迁移。数据不会发送到服务器，也不会跨浏览器同步。
5. 导出按钮备份已保存的配置；导入 JSON 后可预览、编辑，再点击保存。

浏览器存储空间有限。如果图片较多导致保存失败，编辑器会明确提示；可以减少图片后重试。清理浏览器数据会删除本地内容，建议先导出备份。作品链接仅支持 HTTP/HTTPS，只有点击后才会访问外部作品。

作品展示页可直接点击「编辑作品」，编辑封面、名称、分类、说明和链接，并添加、删除或上下排序。封面以最长边 1000 px 的 WebP 压缩保存，前三件同步书房作品墙。保存返回作品预览，关闭编辑面板则放弃未保存的改动。

左下角常驻说明与房间标题已移除。无操作约 5.5 秒后界面工具淡出；移动鼠标、触碰或键盘操作恢复，编辑面板和物件详情打开时保持可见。客厅音响与唱片音乐同步，可直接点音响播放或暂停；陶瓷杯点击续杯升起热气。手柄支持试按摇杆和按键，也可单独更换配色。床头双铃时钟显示设备现实时间，可轻拨铃锤。近看物件时隐藏顶灯模型，照明保持生效。

## 独立材质与模型

- 书房：深胡桃木、原有亚麻与皮革、乳白吸顶灯。
- 客厅：烟熏橡木、圈绒沙发、双环顶灯、宽叶橡皮树。
- 卧室：浅白蜡木、棉织物、褶纹灯罩、绑带帘与干燥燕麦花枝。
- 展厅：洞石、矿物墙面、绒面坐垫、线形顶灯、卷帘、橄榄树与原创三联画。

王冠兔经本机 Blender 从约 63 MB / 200 万面优化至约 3.6 MB / 11.7 万个三角面。修复错误的黑色毛发描边，以独立白毛、红披风、金色王冠及权杖材质和顶点颜色重绘，眼睛使用原有眼部曲面重新定位着色，移除重叠凸出的眼球，并修整鼻口细节。底部贴合展台，模型约 0.80 × 0.84 × 1.11 场景单位，最大占地小于展台。原始下载文件不作改动。重新处理可运行：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python scripts/prepare-sculpture.py -- /path/to/source.glb
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python scripts/refine-rabbit.py
```

## 扩展结构

- `app/live-weather.ts`：天气解析、地点精度与太阳位置计算。
- `app/use-live-environment.ts`：时钟、定位权限、天气刷新与失败状态。
- `app/house-landscape.ts`：共享室外场地、实例化叶片与四窗离轴投影。
- `app/window-craft.ts`：窗户细部。
- `app/house-data.ts`：带宽深的房间注册、整屋边界、平面点选和物件所属房间。
- `app/cafe-layout.ts`：咖啡厅家具坐标、座椅朝向和主要动线。
- `app/cafe-room.ts`：咖啡厅细节模型、独立材质、照明与互动。
- `app/cafe-botany.ts`：咖啡厅层架垂藤、蕨类、窗边花箱与榕树；曲面叶片带原创叶脉纹理，叶片实例化，壁架植物随所属墙体剖切。
- `app/wall-cutaway.ts`：所有房间统一的墙体背面隐藏与临界角防闪烁。
- `app/house-rooms.ts`：三个新增房间、共享门洞、家具细节、交互动画和电视屏幕。
- `app/house-lighting.ts`：四间屋独立顶灯与总开关。
- `app/house-finishes.ts`：独立房间纹理与展厅绘画。
- `app/gallery-model.ts`：用户模型加载、尺寸保护与资源释放。
- `app/television-screen.ts`：原生播放器的空间变换与深度遮挡。
- `app/television.tsx` 与 `app/video-source.ts`：视频播放、来源解析和资源清理。
- `app/computer.tsx` 与 `app/device-settings.ts`：电脑网页与设备设置持久化。
- `app/wall-art-editor.tsx`、`app/art-storage.ts` 与 `app/wall-art-data.ts`：独立画框、压缩与 IndexedDB 图片存储。
- `app/room-data.ts`：个人内容、作品类型、物件注册表和场景 API。
- `app/room-layout.ts`：统一家具占地、朝向、活动行程和主要路线。
- `app/environment-data.ts`：时间、天气选项及类型。
- `app/room-environment.ts`：本地生成的窗景、雨滴动画与光照参数。
- `app/environment-picker.tsx`：时间与天气的简洁控制面板。
- `app/use-visible-viewport.ts`：缩放、窗口和软键盘变化时的可视区域边界。
- `app/room-materials.ts`：本地 PBR 材质加载。
- `app/room-scene.ts`：带物件 ID 的分组、几何、材质、灯光、拾取、相机与动画。
- `app/room-textures.ts`：可复现的木纹、织物、灰泥、皮革及画作、屏幕纹理。
- `app/studio-art.tsx`：作品阅读视图与本地图片预览。
- `app/page.tsx`：极简界面、内容编辑、备份和交互分发。
- `app/globals.css`：昼夜风格、近看状态、桌面和手机布局。
- `scripts/serve-local.mjs`：本地与 Railway 共用的静态服务。

新增物件时，在 `objects` 注册 ID 和文案，在场景中通过 `group(id, x, y, z)` 建模，然后在 `interact` 或页面的 `action` 中连接行为；探索列表会自动包含新物件。增加新的区域可继续使用同一分组方式组合家具，并通过 `RoomApi.focus` 进入区域。作品上限由编辑器与配置验证共同限制，可按需要调整。

- 独立画作上传、压缩、刷新恢复、切换画框与恢复单幅原作；320 × 640 和 844 × 280 窗口下设备设置面板边界检查。
- 未授权定位或选择城市时，小屋加载与本地视频播放过程无外部资源请求；本地服务监听地址核验为 `127.0.0.1:3000`。

需要支持 WebGL 的浏览器；音乐需主动点击开始。手机检查使用浏览器视口模拟，未在实体手机上验证。Three.js 的生产分块会有体积提示，场景仍通过动态导入加载。

## 布局核验

运行 `node scripts/check-layout.mjs` 会检查：房间边界、家具之间的占地碰撞、椅子朝向、工作椅拉出和抽屉全开的活动范围、书柜前取书区及主要路线余量。结果与俯视图生成在 `output/playwright/`。

场景尺寸约定为每单位 0.625 m。沙发到茶几净距约 41 cm，书柜前取书区深 60 cm，主要路线中心距最近家具约 42 cm。这些是虚拟场景中的布局检查，未作为实体建筑施工规范认证。墙面画作在沙发上方；书柜独立靠后墙；雕塑收在唱片柜上；桌面物件跟随桌子父分组，后续移动书桌时不会遗留悬空物件。

## 角色、座位与床上休息

- 点击实体椅子、沙发坐垫、长凳或床上的位置，输入名字并选择形象。点击小人可改名、换装；选择另一张空椅可换座。下方「定位」将镜头带到自己的角色，并显示其他在线角色的所在房间、休息状态和定位入口，不再列出全部空座位；也可手动收起角色。
- 全屋共 **31 个独立位置**：29 个座位（书房 4、客厅 3、卧室 2、展示区 2、咖啡厅 18）与卧室 2 个床位。人物坐标绑定实际家具，工作椅拉出时一起移动；朝向跟随座椅，臀部贴合座面，双腿按参考坐姿自然向前；短腿在较高座椅上悬垂，保持原比例。阅读椅有人坐下时书本移到扶手。
- 身份由服务端读取连接 IP 后生成匿名标识；客户端不能指定自己的身份。本地服务忽略转发请求头；仅在 Railway 环境中使用边缘代理提供并验证为单个 IP 的 `X-Real-IP`。每个 IP 同时只有一个小人，每个位置最多一个人；换位和占位在服务端一次完成，抢占失败保留原位置。IP 不发送给浏览器，应用不写入日志或磁盘。
- 状态每 4 秒同步；在线页面每 25 秒续期，超过 150 秒未响应则释放位置。刷新可恢复仍在线的位置；服务重启或重新部署清空占用。昵称与外观保存在当前浏览器，下次放置时预填；当前小人的外观随服务端状态同步。
- 本地服务器仍只监听 `127.0.0.1`。因此同一台电脑不同浏览器、无痕窗口或标签页使用相同 IP，会共享同一个小人；这不是按浏览器存储生成的多个用户。
- 使用 `npm start` 或 `npm run dev` 都包含 `/api/presence` 服务。直接用其他静态文件服务器打开导出的页面时，座位功能会提示正在连接，不会伪造占座成功。
- 当前提供熊女孩、猫女孩、九尾狐三套完整原模型，均来自用户提供的 GLB，在本机 Blender MCP 中改制。保留完整脸部、头发、服装与配饰，沿原网格连续弯曲髋部和膝盖，单独修整裙摆；不再使用外露球形关节、拼接脸部或随椅高拉长小腿。原始下载文件未修改。
- 坐姿源工程为 `assets/models/studio-visitors-v3.blend`，躺姿工程为 `assets/models/studio-visitors-rest-v4.blend`。网页加载 `public/models/studio-visitor-bear-v4.glb`（约 5.4 MB、101,788 三角面）和 `public/models/studio-visitor-cat-v4.glb`（约 4.9 MB、101,998 三角面），使用 2048 px 本地纹理。多人共享几何与纹理，每个人的配色和姿态独立。
- 九尾狐使用 `public/models/studio-visitor-fox-v4.glb`（约 5.7 MB、100,799 三角面）。完整保留脸部、花饰、和服、九尾和 UV 纹理；坐姿双腿连续前弯，尾扇收拢并抬高下缘，避免占用邻座和穿入坐垫。坐姿宽约 0.60 单位，适配最窄的 0.637 单位卡座间距。黑色和服改色时保留金色刺绣；尾巴保持原来的白毛颜色。
- 九尾狐的坐姿源文件为 `assets/models/studio-visitor-fox-v3.blend`，包含参考、坐姿和网页副本。`scripts/pose-fox-visitor.py` 可在 Blender 的独立初始工程中重建，支持 `STUDIO_FOX_REFERENCE` 指定原始文件。三套 v3 模型保留为 v4 的输入，原坐姿保持不变。
- 衣橱可选择三套原始角色，并调整发色、虹膜、上衣和下装颜色，支持一键恢复当前角色的原配色。原配色直接显示源贴图；改色保留纹理明暗。为保持原模型完整，当前保留各角色原有的发型、服装和配饰，不再提供旧版拼装发型/性别开关。旧版偏好仍兼容读取，未指定角色的访客使用熊女孩。
- 预览可拖动旋转和缩放；保存后才提交，取消不影响已保存形象。换座、改名不会重置形象；抢座失败不会部分更新外观。
- 三种角色均有自然眨眼（偶尔连眨）、轻微呼吸和间歇转头观望。动作按访客身份错开节奏，换座与同步不会重新计时；头发、耳朵和饰品跟随头部，臀部与脚保持原有接触位置，九尾狐的后方尾扇不随头部扭动。衣橱预览使用相同动作。
- `app/visitor-motion.ts` 维护局部动作与实例状态；`app/visitor-eyelids.ts` 依据三套原脸的独立轮廓生成眼睑，沿原贴图采样肤色，原 GLB 和 Blender 工程未被改写。网页隐藏时停止绘制，系统「减少动态效果」开启时人物静止；颜色、深度和点光源阴影使用相同变形。
- `app/visitor-appearance.json` 维护共享选项；`app/visitor-model.ts` 管理角色目录中的模型和保留纹理的改色；`app/visitor-preview.tsx` 与场景共用资源。建模流程在 `scripts/pose-source-visitors.py`；旧版 v1/v2 工程与模型仅保留在本机，不由网页加载或包含在本次发布中。仓库包含 v3 源工程、v3 输入模型和当前 v4 工程与模型；自动备份不提交。
- `app/seat-catalog.json` 是前端和服务端共用的座位目录；添加新椅子时增加目录项，并用 `attachSeats` 将其绑定到家具。`app/seat-scene.ts` 管理模型实例、姓名牌、朝向和拾取；`scripts/seat-presence.mjs` 管理占座规则。
- 验证：`node scripts/check-seats.mjs` 检查唯一 IP、并发抢座、换座、改名、满座、续期和过期；`node scripts/check-visitor-model.mjs` 检查三套模型的体积、面数、完整 UV/法线、座面接触、前伸鞋子和 29 个座位的地面余量。`node scripts/check-appearance.mjs` 检查外观保存、换座/冲突时的数据完整性、颜色验证与旧客户端兼容。
- `node scripts/check-visitor-motion.mjs` 检查 29 个独立节奏在两分钟内的眨眼频率、转头连续性、减少动态效果，以及极限动作下三种角色的座位宽度、座面接触、脚与后方尾扇稳定性。

### 休息和互动

- 点击床的左侧或右侧即可「躺下休息」。角色展开双腿，头靠枕头，持续闭眼并轻微呼吸；「醒来，坐一会儿」使角色坐到对应床沿并恢复眨眼和观望。离开后立即释放床位。床品颜色和床头灯仍可直接调整。
- 「定位」显示自己的位置与其他在线角色；点击角色卡可进入其房间。点头致意和送个心意会同步短暂的场景气泡，发起者有轻微点头动作；每次互动间隔至少 2.5 秒，6.5 秒后气泡消失。自己或对方正在休息时不能互动。
- `scripts/pose-rest-visitors.py` 在本机 Blender 中由完整的原始表面恢复躺姿，保留 v3 的坐姿顶点和 UV。`assets/models/studio-visitors-rest-v4.blend` 包含 Basis / Rest 形态；该脚本由仓库内 v3 工程与 GLB 重建 v4。保持完整连续的身体，不添加外露关节。
- `node scripts/check-visitor-rest.mjs` 校验原坐姿保持、Rest 形态、UV、单位法线、体积和双床位边界。`node scripts/check-seats.mjs` 另验证床位冲突、起身、跨座移动、休息免打扰、互动冷却与过期，以及本地和 Railway 身份识别。
